# Game of Chaos

元胞自动机沙盒。五种模式共用同一套渲染、相机与交互层：

- **生命游戏**：二态（活/死），B/S 规则可调，全局同步，有限网格
- **五行生克**：六态（空 + 木火土金水），按「生我 / 克我」的邻域计数演化，全局同步
- **异步因果**：生命游戏规则，但去掉全局时钟，改成事件驱动 + 光锥约束
- **无限生命**：生命游戏规则 + 无限画布（稀疏存储，坐标可负，没有边界）
- **粒子生命**：离格系统，没有格子也没有「代」，每帧算粒子两两之间的力

零构建：没有打包器、没有 npm 依赖，浏览器直接跑 ES 模块。

## 运行

```bash
# Python（Windows 上一般自带）
python -m http.server 8080

# 或者 Node
npx serve .
```

然后打开 <http://127.0.0.1:8080>。

> 直接双击 `index.html` 也能打开，但 `file://` 下浏览器会拦掉 ES 模块，
> 所以本地起个静态服务器最省事。

## 三种规则

### 生命游戏

邻居数查表，`B3/S23` 表示「死细胞周围 3 个活邻居则出生、活细胞周围 2 或 3 个则存活」。
规则串可改，附 8 个预设。同步更新，边界可选环绕。

### 五行生克

状态编码：`0 空 · 1 木 · 2 火 · 3 土 · 4 金 · 5 水`

- **相生**：木生火、火生土、土生金、金生水、水生木
- **相克**：木克土、土克水、水克火、火克金、金克木

每个格子数八邻域里各状态的数量，然后按优先级判断：

1. **克制**：`克我者 ≥ 克制阈值` 且多于 `生我者` → 变空
2. **生长**：空格，邻居里某元素数量 ≥ `生长阈值` 且压得住自己的克星 → 变成「该元素所生」的状态
3. **转化**：`生我者 ≥ 生长阈值` 且多于 `克我者` → 推进到「我生」的状态

三条都不满足就保持原状。两个阈值在右侧可调，调高偏静态，调低偏沸腾。

**为什么初始状态是区块而不是随机撒点**：五态随机撒点会让每个格子的邻域里同态太少，
规则被噪声支配，画面退化成彩色噪点。成块的初始状态才有「域」可以生长、有边界可以移动。
点「随机」就是重新播一片五行区块。

#### 怎么看规律

二维网格只给某一刻的空间快照，生克是时间上的循环关系，光看格子看不出来。
所以另外给了三层视图：

- **生克流向环**（关系层）：五个节点排成环，外圈实线箭头是相生、内圈虚线五角星是相克，
  线宽 = 本代实际发生次数，节点大小 = 该元素当前占比。能直接看出谁在压谁、哪条链在活跃。
- **五态曲线**（时间层）：木火土金水各一条线，横轴是最近 240 代。看周期、相位差、谁在扩张。
- **单态隔离**（空间层）：点图例里的元素，只留它保持原色，其余压成暗灰，
  用来观察单一元素的域形状和扩张前锋。

#### 三档形态

阈值组合会掉进完全不同的形态，面板上直接给三档：

| 预设 | 生长 / 克制 | 看到的样子 |
| --- | --- | --- |
| 地块 | 3 / 3 | 稀疏群岛，边界缓慢侵蚀 |
| 涟漪 | 2 / 4 | 迅速铺满，同心环一层层往外推 |
| 沸腾 | 2 / 2 | 铺满后持续翻腾，结构不断被打散 |

生长阈值从 3 降到 2 是条很陡的相变线：3 停在稀疏地块，2 会迅速铺满棋盘，
再由克制阈值把「铺满之后」分成同心环和翻腾两种形态。

### 异步因果

跑的还是生命游戏的 B/S 规则，但把「全局时钟」拆掉了：没有第 t 代，每个格子有自己的本地时间戳，
任何一帧都是不同年代状态的拼贴。

- **事件驱动**：每个格子按自己的计划时间排进最小堆，按时间弹出；同一时刻按格子 id 排序，
  所以给定种子结果完全可复现。
- **光锥约束**：读邻居时，只有时间戳 ≤ `now − d/c` 的状态才算「已经送到」，否则只能读到它的
  上一版。这一条不是性能优化，而是把因果结构写进语义；关掉它就等于假设无限光速。
- **两种触发**：周期（每格按自己的时钟更新，带抖动）和邻居触发（只有变化才传播，
  没有扰动时会静止，这本身就是激发介质的正确行为）。
- **本地时间着色**：按每格落后当前时刻的程度取色，越亮越新，越蓝越落后。能直接看到
  「不同区域处在不同年代」。

面板上的「频率」是每格每秒更新次数，「光速」是每格每秒传几格，「速度」滑杆在异步模式下变成倍速。

实现上有个坑值得记：处理完事件后必须把排期清空（`due = Infinity`），否则下一拍一定比旧排期晚，
会被「只有更早才排期」的判断挡掉，结果是首批事件处理完队列就空了。

### 无限生命

生命游戏天生稀疏：死区只要周围没有活细胞，就永远保持死亡。所以没必要给整个平面分配内存——
只存活的格子（`Map<x,y>`），坐标可以是负数，没有边界、没有环绕。

每代只处理「活细胞 + 它们的邻居」这个候选集：活细胞给自己和八邻域各投一票，
候选格里计数 3（或已活且计数 3/4）的就是下一代。代价正比于活细胞数量，而不是面积。

配套的渲染也只画视口内的部分：视口格子少就逐个查，视口格子多就直接遍历活细胞集合。

五行生克没有无限模式，因为「空」在那里本身是要被填充的状态——场会无限向外扩张，
不存在「全部演化完」这回事。异步因果同理，每格一个时钟，无限格就是无限事件。

### 粒子生命

规则搬自 HackerPoet（CodeParade）的 Particle-Life，参数与力曲线与 fnky/particle-life 的 JS 版本一致。
它不是元胞自动机：粒子有连续位置和速度，没有网格、没有「代」。

- **类型矩阵**：任意两种类型 (i, j) 之间存 `attract / minR / maxR`。对角线（同类型）永远排斥，
  半径对称、吸引力不对称——不对称是追逃行为的来源。
- **力曲线**：`minR` 处为 0，中点最强，`maxR` 处回到 0；`r < minR` 时用软核强制排斥，防止近距离力爆炸。
- **更新**：速度累加后积分位置，再乘阻尼；边界可环绕或反弹。

代价是 O(N²)：400 个粒子每帧 16 万次配对。开启「描边」后每个粒子会沿速度方向画一段箭头，能直接看出谁在追谁、团块内部的绕流。默认给「Gliders」预设 + 环绕，最容易看出团块结构；
「Balanced」的力更弱，看起来像带小团簇的气体。

## 部署

纯静态站点，任何能提供静态文件的服务器都行（Nginx / Caddy / 甚至 `python -m http.server`）。

仓库里带了一个同步脚本，只负责传文件：

```bash
SERVER=<公网IP> SSH_USER=<用户> SSH_KEY=~/.ssh/<密钥> ./scripts/deploy.sh
```

它会把文件打包上传到 `/var/www/game-of-chaos`，然后在服务器本机跑一次 `curl` 自检。

Caddy 侧需要一段把路径前缀指向静态目录的配置（脚本不会自动改它）：

```caddyfile
@chaosRoot path /chaos
redir @chaosRoot /chaos/ 308

handle_path /chaos/* {
	root * /var/www/game-of-chaos
	file_server
}
```

改完先备份、再校验，最后才 reload：

```bash
sudo cp -a /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-$(date +%Y%m%d-%H%M%S)
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

站点内所有资源都用相对路径，所以挂在 `/chaos/` 这种子路径下不需要改代码。
注意 ES 模块要求 `Content-Type: text/javascript`，Caddy 的 `file_server` 默认就是。
